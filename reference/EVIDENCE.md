## Observed flow patterns

These sequences describe QA wiring, not validated business recipes:

- Table Fusion → Calculate Columns → three Table Outputs using updateappend, append, and rebuild.
- Two Table Inputs → Column Selectors → Combine Tables; the combined data and Agents feed both Lookup Columns and Join.
- Join branches to filtering, column selection, text cleanup, pivoting, transformation, and grouping.
- Pivot → Table Output → Unpivot → Table Output. Table Output is not necessarily a terminal node.
- Fix Data → Remove Duplicates → Find & Replace → separate Text to Rows and Text to Columns branches.
- Transform Data → Standardize Data → Convert Type → Find & Replace → Table Output.
- Group Rows and Transform Data feed Aggregate Columns, which writes another output.
- JSON input branches to JSON to Rows and Calculate Columns. The latter adds Story and feeds summarization, Ask AI, and translation; translation feeds language detection.
- Separate inputs feed IP to Location, Geocoding, and Sentiment Analysis, each with an output.

## Expanded tickets test

Created 2026-10-02: `tickets-expanded.json` (optional historical artifact). This is a complete standalone eight-node flow, including the original input/extraction steps, with fresh node and schema IDs. If separately provided, paste that optional example into a blank canvas to test it; it is an optional historical artifact, not included in this evidence page. It reuses the same source dataset/column references as the successful first test and has no output-table writes.

```text
Support Tickets JSON → Expand Tickets JSON → Ticket Fields
  → Normalize Status → Add Priority Rank
      ├─ High Priority Tickets → High Priority Queue
      └─ Ticket Count by Priority
```

Five added nodes:

- **Fix Data / Normalize Status:** trims and uppercases status; Open becomes OPEN. Internal spaces are preserved.
- **Calculate Columns / Add Priority Rank:** adds int32 priority_rank with High=1, Medium=2, otherwise=3. For this sample, otherwise means Low; unknown/null priorities would also receive 3, so this rule needs refinement for broader client data.
- **Filter Query / High Priority Tickets:** retains priority exactly High.
- **Column Selector / High Priority Queue:** keeps ticket_id, subject, status, priority, created_at, assigned_to, and priority_rank; removes description and customer details.
- **Group Rows / Ticket Count by Priority:** branches before filtering to count all tickets by priority.

Expected previews: normalized/calculated data has 10 rows; High Priority Queue has TCKT001, TCKT003, TCKT005, TCKT007, each with status OPEN and priority_rank 1; summary has High=4, Medium=3, Low=3. No output ordering is assumed.

Local checks passed: JSON parsing, eight unique node IDs, seven upstream references resolving in topological order, unique output field names, and seven queue fields. ClicData import/execution of this expanded variant is pending. The new use of a CASE expression in Calculate Columns adapts syntax observed in the QA Transform Data node and needs editor confirmation.
